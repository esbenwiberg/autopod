# Checks-only recovery for held empty-workspace artifacts

File collection preserves bytes. It does **not** establish independently passing
Facts, configured checks or review. Ordinary artifact collection remains unchanged,
and infrastructure holds still block ordinary Resume and validation.

`ap recover-artifact-checks POD --json` provides authenticated, read-only inspection.
It reports a provisional selection or refusal and the durable operation, if one
exists. Inspection does not stop, export or execute the retained source. Source
existence and complete content eligibility are established during explicit capture,
not asserted from a diagnosis or a successful inspection response.

Initial support is deliberately narrow: a standalone native local Docker task,
artifact output, ordinary completion, failed status, a settled exact worker run,
current `ready` finalization with no preserved source/worktree/validation result,
complete worker token telemetry and an unchanged unlimited effective task budget. It requires
frozen independent review and enabled executable Facts. No Goal, interactive task,
findings acceptance, linked task, sidecar, web/browser Fact, waiver, pending decision,
uncollected guidance, shared workspace mount, reference input or private registry
is admitted. Another recovery or active execution retains exclusive custody.
Facts must name `create` or `touch` artifacts. Historical `update`/`delete` claims
need a baseline this route cannot establish, so they remain unsupported.

Every current-generation infrastructure report must be a complete typed launcher
need referencing the original frozen v2 execution requirements. Legacy/free-text,
mixed, builder, native platform, credential and unknown needs fail closed. This
route cannot translate a diagnosis into qualification or repair an environment.
It provisions the original frozen immutable software/resources and observes actual
Docker identity, platform, user, capacity and required launchers before checks.
If they remain unavailable, it records a blocked outcome and retains the originals.
No replacement execution profile or new credential/GitHub authority is selected.

Save a JSON file with exactly these fields, using the inspected binding hash:

```json
{
  "id": "operator-chosen-stable-request",
  "expectedBindingHash": "<64-character inspected hash>",
  "reason": "Independently check the retained existing artifact source"
}
```

```sh
ap recover-artifact-checks POD --apply --request exact-request.json --json
ap recover-artifact-checks POD --json
ap recover-artifact-checks POD --reconcile --request exact-request.json --json
```

Selection binds the authenticated human, exact request, logical task, generation,
cycle, original Docker engine/resource, frozen authority, effective token limit,
worker telemetry and complete prerequisite report set. Keep the same file and
authenticated identity after a timeout. A changed request conflicts. Reconciliation
requires a saved admission; it cannot silently create one. The CLI never retries
automatically and never substitutes Resume or another coding task.

Custody precedes a single non-destructive stop. A lost stop response remains
pending until the same request observes the exact stopped original. Stop is never
redispatched. Capture and execution each have a durable one-shot dispatch marker;
interrupted/unknown capture, allocation or checks are retained and are not replayed.
Observe the operation's events after a daemon restart. If no supported observation
can resolve an uncertainty, report it to the execution owner; do not clear custody,
edit the database, wake the original or downgrade to an unaware daemon.

The snapshot uses existing complete artifact inventory/receipt facilities, retaining
ignored reports and prior confirmed copies. Its immutable inventory binds the
independent execution copy, check admission, results and new report snapshot. The
initial reviewer packet accepts at most 1,000 regular UTF-8 files and 500,000 source
bytes (plus packet structure); ambiguous paths, links, binary contents and oversized
packets are refused after preservation. Files are presented as complete additions
with an explicit artifact-content notice. This presentation invents no Git baseline,
commit, branch or ancestry. Git resets, empty-diff acceptance and cached worker review
are bypassed only for this trusted artifact source mode. Frozen enabled phases and
original Fact commands run with the original independent reviewer and task accounting.
No coding agent or automatic correction worker is dispatched; no budget resets or
token caps are introduced.

HTTP 202 acknowledges a durable request, **not** acceptance. A `checked` event with
`outcome: pass` requires exact-source passing checks, every original Fact with an
observed successful command result, fresh independent content review and captured
reports. Failed, missing, aborted, changed-source or infrastructure-blocked evidence
is non-passing or blocked. An `engineResult` alone is not a checked outcome. Original
pod status, infrastructure hold, source, resource and existing snapshots remain held
even after success. There is no publication, approval, merge or deletion authority.

The daemon/API tests use real SQLite and mocked Docker/provider/check boundaries;
CLI tests cover exact request transport, pending/refusal rendering and no retry.
These results do not prove live Docker, Azure, native platform or product acceptance.
This implementation does not operate any original live task. Independent daemon
validation/review and authorized publication of the implementation remain separate.
