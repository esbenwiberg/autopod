# Checkpoint 15: artifact preservation before completion

Desired-behavior regressions exposed both automatic and interactive artifact completion swallowing extraction failures, cleanup proceeding without a preserved copy, and a cancelled lifecycle being resurrected after asynchronous extraction. Collection now publishes a unique generation snapshot only after the adapter completes. Failed, timed-out and superseded copies cannot replace the previous published snapshot. A timed-out adapter retains its source and removes only its own staging directory when it eventually settles.

Automatic failure remains failed with its original container. Interactive failure rejects completion and remains running. Neither cleans up the source or emits terminal success. Lifecycle/container ownership is checked around publication, branch push and cleanup. Completed artifact file APIs select the published snapshot ahead of a stale worktree or live container. Canonical-path checks reject a symlink outside that root.

Resume recognizes settled artifact collection failures before requiring a host worktree. It retries collection without a worker and coalesces duplicate concurrent requests. A repeated extraction failure now returns HTTP 502 instead of a misleading successful response; a subsequent retry remains possible. CLI describes this recovery, desktop maps and presents Retry artifact collection, and mobile routes failed Resume to the actual resume endpoint. Mobile refreshes state after recovery even without WebSocket delivery, and parses daemon error messages for readable feedback. Artifact pods do not show the unrelated validation retry control.

Evidence: final affected daemon suites 456 passes; mobile 108 passes; CLI 22 passes; desktop build and 338 tests pass; all seven package builds pass. An earlier broader container/manager run passed 582 tests with one existing skipped test. The skipped test is not acceptance. Browser interaction against the built mobile client verified failure text, retained Retry, subsequent completion and button removal. The local synthetic server recorded two collection requests and no workers; actual manager tests independently verify collection failure, retry and duplicate calls. Native desktop interaction remains unverified. Full repository validation must run again on a committed final source.

Remaining: adapter success alone does not prove a content inventory or fsync durability. Snapshot publication and journal/path updates are not yet a cross-filesystem/SQLite crash transaction. Recovery after preservation followed by daemon death or cleanup needs explicit reconciliation. Broader finalization push/merge/cleanup effects and external disposition, human-delivery acknowledgments, task-wide provider/rework budgets and other six-workstream acceptance remain open. Optional artifact branch publication retains its existing best-effort behavior and is not a delivery receipt. No production operation was performed. Pending read-only live inspection approval is unchanged.

Receipt normalization removes trailing whitespace and surplus EOF blank lines only; raw logs remain in /private/tmp/autopod-artifact-*.txt.
