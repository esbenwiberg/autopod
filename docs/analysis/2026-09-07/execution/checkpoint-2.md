# Checkpoint 2: preflight capabilities, backup evidence and disconnected operator replies

The goal remains active; this is not closure of any workstream.

Implemented queue binding from the creation snapshot before the first provider attempt. Profile account changes retain the original authorized account. Missing accounts and changed provider identity fail before provisioning with reconciliation guidance. Replaced the unsupported NuGet probe with capability-checked `dotnet package search` and structured result checks. NU1301 alone means unavailable, not proven credential rejection. Provider output is not echoed into errors.

Sandbox Codex config installation now tests effective identity, readable uploads, writable directory and runtime readability. It atomically installs a separate file instead of requiring a non-root executor to chown the root-owned upload. Existing sandbox 0644 and Docker 0600 policies remain. Local real-shell tests deny chown and cover repeated installation, unreadable input and symlinks. Actual hosted-image verification remains outstanding.

A broader regression run exposed a real late-rollout ordering defect: an empty prior-turn file can be filled after the resume byte baseline. The deterministic reproduction fails before the fix. Resumed rollout evidence now also requires an invocation-time timestamp; missing or older timestamps cannot settle the new invocation. Stdout evidence is unchanged. A separate 250ms test harness deadline was insufficient under parallel build load; that one deadline is now 2 seconds, retaining the recovery assertions and short runtime timeout settings.

Backups bind to the actual open SQLite database using canonical source identity. Committed WAL data is included by SQLite online backup. Snapshots receive checksum, integrity, data watermark and timing receipts; low disk headroom prevents creation; pruning touches only finalized matching-source backups. The standalone built restore CLI copies to a private temporary database, verifies identity, freshness, checksum, integrity and watermark, exercises a rolled-back write, and removes the temporary copy. It never opens the live database for writes. Local tests verify preservation of newer active rows, wrong-source rejection, stale rejection and corruption detection. Hosted backup scope and current live data freshness remain unproven.

Build-time release identity and backup health are exposed in health responses. Unknown build identity stays unknown. CLI health, mobile About and desktop Settings display provenance. A built CLI process against an isolated HTTP fixture verifies both JSON and operator text without changing the saved connection or using stored credentials. Browser interaction with the built mobile app verified stale backup and modified release text, plus pending settlement and saved-record diagnostics. It exposed a disconnected-reply UI defect: HTTP acknowledgment did not refresh state without WebSocket events. The mobile fix explicitly fetches authoritative state, retains acknowledgment if refresh fails, and retries the read rather than re-sending the decision. Browser re-verification passed: the selected reply reached the isolated fixture, status became running, and the stale question disappeared without WebSocket delivery. A 390 by 844 screenshot confirmed the rendered state and diagnostic. The temporary browser tab and fixture server were closed.
