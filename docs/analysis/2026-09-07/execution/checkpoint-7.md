# Checkpoint 7 — durable validation retry admission

All six workstreams remain open. This checkpoint adds local validation admission and operator controls; it is not task-wide agent/provider retry completion or live acceptance.

The actual validation entry points now admit work through SQLite migration 147. One immutable task policy pins automatic transient backoffs. Admissions span the original pod and linked fixes; Resume, manager reconstruction and database reopen do not renew the allowance. Each admission captures trusted source/contract/command/environment/implementation hashes where available, provider/account/model binding, unique execution ID and lifecycle generation. Real source capture reads tracked and untracked non-ignored file content, including changes hidden by assume-unchanged. Commit-ID-only changes do not prove changed inputs. Files are bounded and read in chunks; unknown identities never prove change.

Unchanged nonretryable or interrupted work requires a known changed input or a one-use human authorization with a reason and stable request key. Authorization is tied to the latest failed admission and selected pod; reuse after a lost response returns the same record. Provider binding changes are denied even with a retry authorization, pending explicit provider reconciliation. Admission and execution claims are separate, with persisted not-before timestamps, unique active task admission and a conditional generation/decision-aware start. A human decision pending at admission or arriving during backoff prevents execution. Restart settles interrupted admissions as unknown, retaining unknown duration rather than fabricating time.

Measured engine duration is recorded once per executed admission. Backoff and cancelled-before-start admissions are not executed validation time. Denied initial admission preserves previous validation evidence and parks the pod. If an authorized validation actually executes and fails, denial of the following automatic retry still preserves that executed result in durable validation history.

The authenticated API exposes retry accounting and separate authorization. It rejects absent/invalid authentication and forged actor bodies. CLI adds retry-state, authorize-retry with required reason/request-key, and Resume. Mobile and desktop show admitted versus executed validations, cumulative transient allowance, measured duration and interrupted unknown work. Human authorization and Resume remain separate controls. Mobile localStorage and native UserDefaults preserve request keys through uncertain responses; native drafts are scoped to daemon URL and pod. Controls are unavailable while the pod awaits a separate human decision. Desktop controls are available independently of cost-card loading.
