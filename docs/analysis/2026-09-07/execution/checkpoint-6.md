# Checkpoint 6 — scheduled collection and durable human triage

All six workstreams remain open. This is local implementation and verification, not live activation or goal completion.

The actual scheduler now accepts an explicit version-1 scan policy and produces durable reports without creating a coding pod. Fresh strict-fetch worktrees feed a deterministic Git-object collector. Stack names are context only; exact branch deltas never expand. Optional rolling windows freeze the report creation time, select first-parent committer-time commits and record their exact identities. Empty windows compare head to itself. Noncontiguous timestamp histories fail closed instead of admitting out-of-window changes. Windows containing the root use an actual empty tree object in the disposable local Git store. The scan is a net tree delta, not a search for transient secrets added and removed between its endpoints.

Secretlint uses its actual installed versions and opaque baseline identities; new findings are redacted and stable across line changes. The npm adapter accepts v2/v3 lockfiles, runs the supported audit command in a disposable directory without repository scripts/config, includes dev/optional/peer dependencies, and validates coverage counts. Public npm advisory lookup sends dependency metadata to that registry. Other lockfile ecosystems are explicitly incomplete. This implementation does not claim pnpm, Yarn, NuGet or Python audit coverage. Scanner failure/unavailability retains a null finding count and cannot produce a clean result.

Reports commit before optional bounded judgment. Judgment captures the configured provider/account/model before collection, has no tools or repair authority, disables SDK retries, caps input/output and has a 15-second request timeout. Unsupported binding fails closed. Measured judgment tokens/time are recorded; unavailable cost stays null. Empty deltas make no judgment call. Interrupted or late judgment cannot overwrite the terminal restart observation. The report, stable unresolved findings and immutable human decisions survive worker deletion and database reopen.

Human-only authenticated API triage requires a reason, selected finding identities and stable request key. Selection records no worker. A separate launch consumes that durable selection, verifies the repository still matches, and atomically creates a pod plus dispatch receipt. Pod-created publication and enqueue wait for the outer SQLite transaction, keyed to the unique execution identity. Rollback or friendly-ID reuse cannot publish an uncommitted worker. Duplicate launch returns the same receipt even after worker/job deletion. Selection is not proof of resolution or patch delivery.

CLI adds explicit scan creation/configuration, report review, idempotent triage and selected repair launch; run/catchup responses distinguish reports from workers. Mobile adds a report inbox and review flow with durable retry drafts and separate selection/launch controls. Desktop adds policy/report review, explicit triage/launch, persisted retry drafts, nullable scanner counts, report-aware schedule responses and events. Native UI interaction remains unverified; compilation and client tests are not that proof.
