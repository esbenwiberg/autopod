# Checkpoint 47: closed PR history and retained-source recovery

Migration 163 adds immutable open/closed source-bound PR status history, separate from merge confirmations, plus a logical-task index for merge projection. Observations verify the intended source SHA, repository and target branches and store bounded source metadata rather than provider feedback bodies. Duplicate unchanged observations do not inflate history. Source-bound closure and reopening survive disk close/reopen. A new opening observation must match the original source; closure never becomes a merge confirmation or resolves an ambiguous request. Canonical PR status admission guards cover equivalent intents, while task-level disposition counts use that task's source-bound history. Confirmed merges remain a separate, dominating fact in accounting.

The actual merge poller now records verified closure, moves the pod to failed with original resources retained, emits an actionable reason and stops polling. It does not kill the container, publish source, merge, create a fix pod or restart a worker. Planned and acknowledged-unmerged requests can recover after the existing PR is reopened: explicit Resume revalidates retained source, then a separate explicit approval requests delivery. An unacknowledged earlier request remains ambiguous after closure/reopening and blocks another merge. Already validated source encountered during explicit approval remains validated, with guidance to reopen and retry the available approval action; no invalid lifecycle transition or unavailable Resume instruction is introduced. No new PodStatus or Profile field was added.

The task projection now reports last-recorded closed PRs separately from merged and unresolved PRs. CLI, mobile and desktop show the optional closed count and retain explicit unavailable behavior for older evidence. The desktop decoder accepts older summaries that contain merge counts but omit the new closed count. None of these projections claim live provider status or infer who closed/merged a PR.
