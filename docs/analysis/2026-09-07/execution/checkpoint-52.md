# Checkpoint 52: stale streams do not finalize replacement workers

Five RED cases demonstrated real event-consumer boundary failures: an obsolete stream ending or throwing could report failure against a replacement; a stale completion still extracted the replacement container's session state; a replacement arriving during session synchronization had its provider attempt closed; and an already superseded lifecycle still began a task run and consumed its generator.

The consumer now captures its generation, exact container and runtime/provider/source-location binding before initialization, including calls without an explicit lifecycle argument. Already superseded calls return stopped before opening a task run or consuming events. Iteration, terminal errors and finalization require both that lifecycle and the in-process run owner. Session synchronization uses the captured pod/container rather than rereading a replacement by pod ID; it is not dispatched for a stale owner. Ownership is rechecked after the await before provider closure or failover handling. A superseded finalizer does not stop a replacement run's poller or clear its bookkeeping. Each old run's own settlement waiter is still resolved. Direct continuation callers stop before credential persistence and completion callbacks when consumption reports stopped.

Control disposition and historical run evidence are separate. A recorded old success or failure is retained even if control must stop before settling a replacement. Later owned failures remain failures; a previously accepted completion is not used to erase them. No missing terminal event is manufactured as success for a superseded run.

The first corrected focused suite passed five cases. The broader lifecycle, provider and task suites passed 587 tests, including pause and failover regressions. The final focused suite passed eight cases covering both observed success/failure and pause quiescence (530 unrelated cases excluded by the filter). Build and configured DTS passed before the final binding refinements. The full required pipeline passed on clean source b78bcdf4e4553b62c6dfc00f4043003a03c7ef78: all 15 tasks, 5,026 daemon tests with one platform skip, 118 mobile tests, 244 CLI tests, configured typecheck, audit with no known vulnerabilities and secret scan. HEAD and worktree remained unchanged; exact identity and output are retained.

This closes local event admission and final-callback ownership gaps. It does not cancel a session extraction already dispatched before replacement, make its filesystem publication atomic, fence every await within individual event handlers, or provide cross-process invocation/cleanup idempotency. Pending commit-poll callbacks also require their own ownership guards. These remain explicit follow-up work, alongside task-wide provider retry budgets, native/operator interactions and live acceptance. All six workstreams remain partial; no provider calls, deployment or production mutation occurred.
