# Checkpoint 40: bind approval merge requests to preserved source

Approval now passes the commit SHA from its confirmed durable source publication into existing-PR and newly-created-PR merge requests. A successful rebase replaces the earlier source receipt used for that request. GitHub CLI uses --match-head-commit and omits --auto for a source-bound request; its follow-up observation must report the same head. GitHub REST checks the fetched head and sends the expected SHA in the merge request condition. ADO checks the observed source, submits that exact lastMergeSourceCommit and checks the source in its completed response. Missing or invalid supplied identities fail closed. PrMergeStatus exposes the observed source SHA when available, separate from the merge commit.

GitHub REST now requires an explicit boolean merged=true response; an HTTP success alone is insufficient. ADO requires completed status, and does not invent auto-complete from an active response lacking an identity. Source branch deletion is removed from all three merge transports: merge success does not prove that a branch has not advanced since the merged commit. Durable cleanup remains required and outstanding.
