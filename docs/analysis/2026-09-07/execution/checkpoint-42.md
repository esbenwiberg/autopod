# Checkpoint 42: exact merge target and final lifecycle admission

GitHub repository/PR parsing now uses the actual URL hostname and complete supported path instead of matching an unanchored github.com substring. Invalid hosts, malformed identifiers, ambiguous paths and encoded path separators fail before GitHub API reads, merges or review replies. HTTPS/SSH/scp repository forms, dotted names, normal PR tab URLs and trailing slashes are supported. Authenticated HTTPS repository URLs still normalize to owner/repository without emitting credentials; embedded credentials in a PR address are rejected. Parser failures never include the supplied address. The GitHub API remains github.com-specific; no Enterprise support is inferred from this change.

Approval now supplies the confirmed publication repository and source branch plus its resolved PR base, alongside the captured source SHA. GitHub CLI verifies its returned PR identity, head/base refs, source SHA and non-fork status before mutation and again afterward. GitHub REST checks both source and base repositories/refs, submits the existing expected-head SHA condition, and observes the final PR identity fields and explicit merged disposition after a successful merge response. ADO verifies the configured repository, exact refs and non-fork source before PATCH and verifies the completed response afterward. Repository equivalence is bounded to supported GitHub remote forms and the canonical/legacy ADO URL forms; unknown aliases are not invented. The final source and target must still match before a provider adapter returns merged=true.

A synchronous onPrepared admission hook now runs after provider preparation and authentication, immediately before the merge command or HTTP mutation. Approval uses it to recheck the captured lifecycle/resource identity and unanswered-decision guard. GitHub CLI invokes the hook after its asynchronous credential lookup, and ADO invokes it after token retrieval inside rawFetch; GitHub REST's stored credential path has no intervening asynchronous lookup. A generation change during preparation is rejected before the test mutation begins, and resources remain retained. This hook provides the boundary needed for the next durable merge journal; it is not itself durable admission.
