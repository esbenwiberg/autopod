# Checkpoint 54: do not replay an uncertain worker turn

Two RED cases demonstrated that validation-feedback Resume was invoked twice after an Azure transport timeout, both before any event and after worker activity. The outer handler assumed that an error code proved an idempotent setup failure. Inspection of the runtime showed that the same generic error can escape different stages; absence of an event does not prove absence of execution.

The whole-turn retry loop is removed. Validation feedback now makes one Resume invocation, retaining a clear unverified-execution-outcome failure for generic Azure timeouts. The existing failed validation remains in history, the workspace/container remain retained, and no replacement worker is launched. The previous diagnostic fixture that expected this broad replay now asserts the desired retained uncertain outcome. Known idempotent Codex configuration-command retries remain unchanged inside codex-runtime.ts, where command identity and the pre-launch boundary are established.
