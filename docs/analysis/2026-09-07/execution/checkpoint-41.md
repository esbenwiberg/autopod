# Checkpoint 41: reject ADO PR URL repository substitution

ADO previously extracted the final numeric path component of a supplied PR URL and issued requests in the manager's configured repository. A foreign organization, project, repository or hostname could therefore select the same-numbered PR in a different repository. All ADO status, merge and review-reply paths now validate the full address before requesting credentials or issuing HTTP calls. The address must use HTTPS, omit embedded credentials and non-default ports, contain an exact repository/pullrequest path and a positive safe integer identifier, and match the configured organization/project/repository. Canonical dev.azure.com and equivalent organization.visualstudio.com URLs resolve to the same configured organization. Explicit positive numeric references remain scoped to the configured repository, preserving the existing interface. Project/repository aliases or case differences that do not compare exactly need reconciliation; no unverified GUID/name equivalence is inferred.

The new RED suite failed 11 cases: ten bad addresses were accepted by the read path and a matching URL with trailing slash/query was rejected; one existing legacy-address case passed. The corrected suite invokes all three operations for every bad address and proves zero credential requests and zero HTTP calls. Valid canonical/legacy/numeric references use the exact configured endpoint. Three provider/durable suites passed 81 tests after the numeric-reference compatibility check was added. An initial formatting check identified a test string concatenation; it was corrected, and root Biome and diff checks pass. Full validation follows on committed source.

No provider request, external reply, merge, deployment or lifecycle mutation was made during verification: HTTP and credential retrieval are local fixtures. This closes address substitution in the ADO adapter, not all source/PR/base identity or lifecycle requirements. W1.3 remains partial: persist source-to-PR merge admission, reconcile legacy merge_pending rows, guard poller merge/self-heal and cleanup, connect other publication callers, and surface durable evidence on supported operator interfaces. Cross-process resource ownership, required native/live acceptance and all other outstanding workstreams remain in acceptance.json. The previously rejected production metadata export is still awaiting specific authorization.
