# Checkpoint 50: historical PR aliases retain admission and accounting authority

Five RED regressions reproduced that historical raw ADO aliases bypassed ambiguous, scheduled, merged and closed PR admission guards, and malformed identifiers were counted as separate unresolved PRs. Current writers canonicalized identities, but comparisons with immutable older rows did not.

The shared identity parser now supplies a connection-local SQLite read projection used by the journal and task accounting. It preserves stored intent/request/observation bytes and normalizes supported GitHub and ADO aliases on read. Values larger than 4 KiB or with unsupported shapes are rejected before the SQLite-to-JavaScript boundary. No persistent schema, migrations or historical receipts change. The projection retains row ordering for lifecycle lookup. Every connection registers its own projection, including after restart.

Admission and source-bound status reconciliation compare canonical identities inside the existing immediate transaction. An unsupported retained identity conservatively blocks new merge admission across the database: it cannot prove that the old row refers to a different PR. The error requires journal reconciliation. Task merge totals become unavailable with an explicit diagnostic if any retained identity cannot be compared, rather than asserting there was no recorded request. This availability decision and the scalar counts use one SQLite statement. Other task accounting and cost fields remain available. Valid alias rows count as one PR; historical admissions prevent a false merged-without-recorded-request classification. Source, target, lifecycle, unresolved-decision and immutable receipt guards remain intact.

The corrected initial journal/accounting suites passed 45 tests. Expanded journal, actual HTTP, task accounting and pod lifecycle suites passed 689 tests. They exercise ambiguous/scheduled/merged/closed aliases, reopening, immutable rows, an actual file database close/reopen, exactly one admission, and bounded task/cost HTTP responses with a one-MiB malformed identity and malformed legacy receipt bodies. The daemon build and configured DTS checks passed. After making availability and totals atomic, the final journal/accounting/HTTP suites passed 133 tests. Full verification of the final committed checkpoint source remains required.

This is local regression evidence, not provider, production or historical fleet diagnosis. Existing CLI/mobile/native optional merge-unavailable rendering remains in place; no new visual controls are introduced. Full operator and live acceptance remains outstanding. The projection may scan retained identity metadata when matching aliases; no performance improvement is claimed. Supporting additional provider address forms, manual repair of corrupted valid-but-inconsistent request identities, and durable cleanup/source inventory still require further work. All six workstreams remain partial. Continue with those criteria after full verification; no deployment, external merge, push, paid call or live lifecycle mutation is authorized by this checkpoint.
