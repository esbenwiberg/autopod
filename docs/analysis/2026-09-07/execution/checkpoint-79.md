# Checkpoint 79: exclusive outer run admission and atomic initialization

Three RED actual-manager cases reproduced overlapping outer event consumption from the same manager, a second manager and a linked pod in the same logical task. Each second stream executed instead of being refused. A same-manager duplicate also replaced the in-memory owner of the original run. Production runtime spawn/resume adapters expose async generators; the common consumer boundary is reached before their first iterator pull. No paid provider was used in these tests.

Starting a new task-agent run now checks for an unfinished run in the same logical task inside its SQLite transaction. A second run receives TASK_AGENT_RUN_ACTIVE with an explicit wait/reconciliation message. Existing identity lookup remains idempotent, but the manager creates a new completion cycle for each requested consumer, so that lookup is not reused as authorization to execute a second stream. Intentional reruns with distinct logical task identity remain independent. The check survives database reopen and separate connections; completed settlement releases it. No new migration or invented runtime timeout is introduced.

The manager initializes bound profile, completion cycle, task run and provider segment inside the existing managed atomic boundary. It registers the in-memory run owner only after commit. Rejected admission therefore rolls back its new completion cycle, does not pull the second iterator and leaves the original owner able to finish. A provider-segment initialization fault rolls back both the new completion cycle and task run without changing the pod. The existing provider-segment fencing and immutable settlement rules remain intact.

Four initial corrected overlap/initialization cases passed, followed by 630 tests across five affected manager, task-ledger, unit-of-work, completion-journal and provider-attempt suites. Added disk reopen/two-connection tests retain the active claim and allow an independent task; an explicit original settlement permits the linked run. The tests are local synthetic event streams and real SQLite, not live provider or multi-process load acceptance. Existing API error handling/operator failure fields are unchanged; no native/browser interaction is newly claimed. The required full pipeline follows the scoped source commit with VITEST_MAX_WORKERS=4 recorded.

All six workstreams remain partial. An unfinished durable run after a lost controller remains unresolved and blocks automatic new admission; restart is not proof that its provider process stopped. A verified stale-run reconciliation path and explicit operator presentation remain required before this execution-admission workstream is complete. Other outstanding criteria include immutable container ownership for run recovery, sequential repeat-failure/rework limits, future spend reservation, deletion-resistant accounting, host CLI provenance and gated live/native acceptance. Continue with recoverable exclusive-run ownership and observed-termination reconciliation; do not reset active claims merely to make Resume pass.
