# Checkpoint 30: retain unconfirmed approval delivery

Normal approval no longer completes after a fallback branch push failure or an unconfirmed failed PR merge. These failures return to the existing validated state with an actionable persisted failure reason and HTTP 502 APPROVAL_DELIVERY_FAILED, retaining worktree/container and suppressing cleanup/completion/dependent dispatch. An explicit retry reuses retained work after a manager restart without spawning a worker. Successful delivery clears only its own prior failure reason. PR creation failure already returned to validated before this checkpoint; the changed behavior there is an explicit error response and durable actionable reason, not a newly introduced retained state. The prior checkpoint's broader description was inaccurate on that specific path.

An unavailable existing-PR review lookup no longer proceeds with a merge. Newly created PRs now consult review status too; pending reviews or unavailable status retain the new PR in merge_pending without issuing merge. Existing pre-merge push failure/conflict handling remains merge_pending. A failed merge followed by authoritative merged status remains a confirmed success; closed-unmerged or unavailable fallback status is never success. Unexpected queued preparation/rebase failures retain the source and return an explicit error.

Normal approval retains original-generation/status/resource anchors across status callbacks, credentials, queued delivery entry, pushes, rebases, PR create/status/merge waits, catch paths, metadata persistence, cleanup and final publication. This does not make external operations interruptible or implement durable cross-process approval intents. Existing decision checks remain enforced. Completion activity now follows the persisted complete transition and identity check.
