# Checkpoint 22: retain interactive sources when synchronization fails

Two actual-manager RED tests proved interactive branch completion could report success, push and clean up after both workspace sync and archive fallback failed, or when a live branch container had no host worktree. The first case could remove the only complete copy of the user's work. Tightening the later deletion threshold did not establish source preservation.

Completion now stops before push and cleanup for both cases. It returns WORKSPACE_PRESERVATION_FAILED (502), keeps the pod running with its container/worktree retained, and records an actionable failure reason for the current lifecycle. The ordinary branch deletion guard remains in place after successful synchronization. Explicit no-output behavior is unchanged. A later explicit completion retry can succeed after synchronization is repaired; it clears only this preservation failure's current display reason and starts no worker. Prior error activity remains recorded.

The actual manager test verifies retained resources, no push/cleanup/kill/stop/completed event on failure, and a single branch push with completion after repair. Three affected daemon suites pass 542 tests; all seven package builds pass. A real CLI command against a loopback HTTP fixture verifies failure propagation without printing completion and success only after a second explicit command. The workspace CLI suite passes 22 tests. Fixture responses are not provider or live-daemon evidence. Native interaction remains unverified; mobile currently has no normal interactive-completion action, and this checkpoint does not add one.
