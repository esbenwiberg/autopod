# Checkpoint 69: reachable bounded scan history

The existing report list stopped at 100 newest reports and had no continuation path. A new report-page endpoint and typed summary contract return at most 20 report summaries, with a schedule-scoped last-report cursor. The SQL projection omits collection and judgment payloads, reports unknown finding counts and judgment status as null with bounded diagnostics, and does not rewrite malformed rows. Ordering uses created_at then id, with keyset continuation rather than offsets. The original full-report list and detail APIs remain available.

Two initial RED repository cases now pass. A 121-report fixture with equal timestamps proves complete traversal without duplicates, excludes a newer insertion from continuation, serializes to disk and reopens before continuing, and rejects missing or cross-schedule cursors. A malformed collection/judgment fixture remains byte-identical while its summary exports no payload and no fabricated zero. The actual authenticated manager/route test verifies the endpoint, summary shape and invalid cursor rejection alongside durable human selection and single repair creation.

CLI adds schedule report-page with --before while preserving the existing reports command's array output. Mobile and native inboxes load older pages, deduplicate IDs and fence stale responses. Mobile provides a read-only refresh, and its interaction tests prove previous items remain and a late page cannot leak into another selected schedule. Native keeps its existing report-detail/triage path and gains typed page decoding and continuation.

Native HTTP fixture testing exposed encoded-query path construction in the new continuation method. Inspection found the same checkpoint-67 issue in provenance opt-in. Both now use the request builder's structured query argument. The first provenance test was insufficient because missing optional latest decoded as nil from the fixture's generic response; strict request URL assertions were added. Restoring the old path reproduced two RED request-boundary failures (query text in the path and absent query), then the corrected implementation passed. Checkpoint 67's native model tests remain valid decoding evidence but did not prove request URL correctness; this checkpoint supplies that missing proof.

Four affected daemon suites passed 591 tests; repository suite alone passed seven; CLI passed five; mobile passed two; three native request/client tests passed after corrections. All seven configured build/DTS tasks passed, with a final mobile build after applying existing button styles. Native app interaction remains unverified. The local browser loaded older synthetic reports, opened an older report's unresolved findings, and refreshed history without collecting a report or recording triage. Final screenshots were visually checked at 390px phone width and a wider browser viewport; unknown counts and incomplete status remain explicit. The local fixtures and browser pages were closed/stopped.

All six workstreams remain partial. This is report-history pagination, not unresolved-finding or decision pagination. More than 1000 unresolved findings currently blocks detail/selection; that next criterion requires bounded discovery and direct validation of human-selected IDs, not silently truncating authority. Live schedules, malformed live-report diagnosis, native interaction, production freshness/deployment and paid acceptance remain outstanding. Full required validation follows this source commit.
