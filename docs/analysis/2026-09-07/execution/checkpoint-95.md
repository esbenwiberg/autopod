# Checkpoint 95: cumulative outer worker transient allowance

Two actual-manager REDs reproduced unlimited outer retries after classified throttling or provider outage across a reconstructed manager and a linked pod. The worker stage now recognizes the existing transient/provider_unavailable classifications, freezes a task-wide allowance at initial admission, records transient retry admissions and rejects further retries when that allowance is exhausted. New tasks default to one-second and five-second cooldowns. Changing the injected/configured allowance later cannot enlarge the frozen task policy. Existing zero policies remain zero. Legacy worker history without a recorded policy gets no newly inferred allowance; another retry requires a recorded human permission. Source changes do not reset a provider failure allowance. Quota failover retains its existing separate authority path and unknown worker failures remain outside this new transient policy.

The immutable retry deadline is checked before iterator entry. Early timer wakes are rechecked, stalled/regressing clocks cannot run past the bounded wait loop, replacement resources retain ownership, and pending human decisions still block execution. Only an actual future deadline enters the asynchronous wait path. The first broad run exposed three pause-quiescence regressions from introducing that path for initial/no-wait admissions. The corrected path preserves the existing suspension consumer behavior; nine targeted cooldown/pause cases and the five affected suites passed. One test expectation initially demanded rejection for a superseded run whose established result is stopped; it was corrected while preserving the zero-pull/zero-execution and replacement-resource assertions. A parameterized fixture initially spread backoff arrays as arguments; its two fixture failures are retained with the corrected object-row test.
