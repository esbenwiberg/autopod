# Checkpoint 74: unreadable scan findings and human decisions

Six RED cases reproduced whole-page failures from malformed finding/decision JSON, unsupported finding shape, mismatched embedded finding identity, oversized finding evidence, and an entirely unreadable first page. Finding bodies are now projected in SQLite only up to 64 KiB, decision selections up to 64 KiB, actor JSON up to 16 KiB and reason text up to 16,000 bytes. A dedicated reader validates supported shape and selection/human identity. Finding payload identity must match its actual database row. Unsupported evidence stays stored and returns a bounded diagnostic rather than a selectable placeholder. This read limit can make unusually large otherwise valid legacy evidence unavailable; it does not truncate it into an authoritative finding.

Paged review preserves healthy rows and reports omitted record IDs and actionable diagnostics. Continuation uses the last database row examined, including when every displayed item is unreadable. The original legacy unpaged methods fail with a reconciliation error rather than silently omitting findings/decisions. Direct selected-finding reads and decision reads enforce the same validation before triage or repair creation. No migration or immutable-row rewrite was introduced.
