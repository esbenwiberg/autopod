# Checkpoint 43: durable approval merge admission and recovery

Migration 161 adds immutable merge intents, request admissions and provider observations. Each intent binds the confirmed source publication, logical task, lifecycle generation, PR identity, repository, head/base branches, expected commit and merge method. An immediate SQLite transaction rejects concurrent ambiguous requests, stale resources, unanswered decisions and unconfirmed publications. Acknowledged pending attempts remain distinct from a single logical merge confirmation. Scheduled auto-merge requires reconciliation before another admission. No historical merge records are fabricated.

Approval uses the provider preparation callback to persist admission before mutation. Lost responses preserve the original resources and return an actionable delivery error. Explicit approval after manager restart reconciles the original admitted source and target without publishing, rebasing or merging again. A read-only local Git inspection must also match the retained publication before recovery can reach cleanup; dirty source or a changed head keeps resources retained, even after an external merged fact has been recorded. Recording that historical fact does not grant authority to a replaced or deleted lifecycle. The publication ID now crosses the coordinator boundary, including the original null PR URL before new PR creation, without rewriting publication history.

GitHub CLI, GitHub REST and ADO status projections expose recovery identity only when the requested PR identity, source refs and non-fork evidence are available. Bound merge responses include their verified source and target. Legacy adapters that skip durable admission cannot authorize successful approval. Unavailable status after new PR creation returns to retained validated state; a known review requirement still enters the existing pending flow.
