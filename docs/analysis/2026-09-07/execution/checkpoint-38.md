# Checkpoint 38: persist source publication admission and confirmation

Migration 160 adds immutable publication intents and receipts, tied to logical task and pod generation. Admission records exact repository/branch/ref/commit/tree plus hashed lifecycle/resource identity before the local Git adapter issues the push. Confirmation requires the same generation, status, profile name, worktree, container, branch/base, execution target, PR URL and output mode, no unanswered decision, and a remote commit matching the admitted commit. An uncommitted outer SQLite transaction cannot grant admission. Replayed identical source produces one intent and preserves its first immutable confirmation; recorded evidence survives deletion of its worker pod through logical-task ownership.

publishSource is connected to approveSession's no-change branch preservation and existing-PR initial/post-rebase pushes. Legacy adapters returning no proof fail before merge or cleanup. Existing lifecycle error paths retain validated state/resources and explicit repair/retry.
