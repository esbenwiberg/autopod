# Repair-continuation wire fixtures

`repair-continuation-v1.json` is the small client fixture. Its available inspection
has `sourceHead: null`, matching production; its opaque retained operation/custody
ID is deliberately different from the external request replay key. Its qualification
bindingDigest is the real canonical SHA-256 of its binding, not a placeholder.

`repair-continuation-backend.json` is an unmodified capture from the real manager
lifecycle and `operation()`/`inspect()`/`preview()` producers in
`packages/daemon/src/pods/repair-continuation.test.ts` (test “feeds actual
inspection…”). It contains claimed, qualified-before-coding, failed qualification,
and sealed/validated projections. Restart projections reconstruct SQLite with a new
process epoch: sealed-but-unsettled checks stay unknown (with historically consumed
coding admission); checked success/failure stay consumed; unsealed unsettled coding
stays unknown. Inspection includes those same nested operations. The fixture uses real SQLite/Git and mocked
container/probe/runtime/validation infrastructure. It is **not live qualification
proof**. Evidence IDs are retained verbatim, not rewritten to request keys.

For a fresh producer-to-native regression, set `REPAIR_CLIENT_PRODUCER_FIXTURE` to
an absolute temporary JSON path for both commands, run from repository root:

```sh
SKIP_DB_TESTS=0 REPAIR_CLIENT_PRODUCER_FIXTURE=/tmp/repair-client-wire.json \
  npx pnpm --filter @autopod/daemon exec vitest run \
  src/pods/repair-continuation.test.ts --maxWorkers=1
REPAIR_CLIENT_PRODUCER_FIXTURE=/tmp/repair-client-wire.json \
  swift test --package-path packages/desktop --no-parallel \
  --filter 'AutopodClientTests.RepairContinuationTransportTests'
REPAIR_CLIENT_PRODUCER_FIXTURE=/tmp/repair-client-wire.json \
  swift test --package-path packages/desktop --skip-build --no-parallel \
  --filter 'AutopodUITests.RepairContinuation'
```

The backend test always runs the actual CLI correlation validators against fresh
producer results. Capture is opt-in and never rewrites committed fixtures during
normal tests. Native tests use the fresh capture when the environment variable is
set, otherwise the committed backend capture. CLI tests also consume the capture.
Keep client/native processes separate; these tests never call a live daemon.

## Canonical binding identity

The shared pure `canonicalConfiguration` is the daemon's original algorithm:
recursive UTF-16 key ordering, preserved array order, ECMAScript JSON primitive,
number and string spelling, and SHA-256 over UTF-8. Extraction does not change
historical digests. CLI hashes the strict parsed binding; no daemon import.

Swift hashes the **complete decoded wire binding**, not JSONEncoder of its typed
projection. The strict v1 binding schema contains only objects, strings, literal
version 1, and nonnegative safe-integer generations (<= 9007199254740991).
Resource floats/arrays/nulls/bools are NOT binding members; resource configuration
is represented by executionContextHash. The native decoder checks these bounds
and the exact binding/source/image key sets before accepting a digest, including
unknown fields even if an altered response carries a matching digest. An extended
binding schema needs an explicit decoder update. Unpaired UTF-16 surrogates are
rejected by JSONDecoder, never normalized into accepted identity. Strings preserve
Unicode composition and use JSON.stringify escaping (not slash escaping); integer
wire spellings such as 1.0 canonicalize to 1, as in JavaScript.

`configuration-digest-vectors.json` is generated by
`configuration/configuration-digest.test.ts`. It pins canonical bytes and backend
SHA-256 for nested objects, safe-integer limits, UTF-16 key order, composed and
decomposed Unicode, astral characters, slash/control escaping and equivalent wire
escapes. It also pins nested arrays/nulls/bools/resource floats and exponential
number spelling for JS, and verifies native rejection of these **out-of-binding**
representations rather than approximate numeric serialization. Regenerate only
explicitly with `SKIP_DB_TESTS=0 REPAIR_DIGEST_FIXTURE=1 npx pnpm --filter
@autopod/daemon exec vitest run src/configuration/configuration-digest.test.ts`.

## Pinned schema string semantics

`repair-continuation-strings.json` is generated by the actual pinned shared schemas
in `repair-continuation-unicode.test.ts`, using the real backend capture as the
operation baseline. These are synthetic boundary variants, not new qualification
or checked facts. The fixture records input, schema success, canonical output and
a consistent JS canonical binding digest, including for invalid key spellings.
Regenerate explicitly with `SKIP_DB_TESTS=0 REPAIR_STRING_FIXTURE=1 npx pnpm
--filter @autopod/shared exec vitest run
src/schemas/repair-continuation-unicode.test.ts`.

Zod 4.6.7 string min/max count Unicode code points. Native repair string bounds
therefore use Unicode scalar counts, not UTF-16 units or grapheme clusters.
Request construction and UI enablement share the same canonical request validator.
Only explanatory text/reasons use ECMAScript trim: FEFF is whitespace, NEL is not.
The journal receives a valid canonical request before the only POST; invalid
drafts neither create pending intent nor require clearing a journal. Existing
journal entries are never normalized or rewritten. Repository/resource identities
retain exact bytes, including combining sequences and whitespace.

The strict binding decoder checks ASCII spelling at the first Foundation keyed
container enumeration, before building its own Swift dictionary or comparing key
sets. The Kelvin-sign `resourceKey` alias and non-ASCII source/image keys are refused,
even with consistent raw digests. Generic canonical byte tests still exercise
Unicode keys independently; they are not accepted binding schema members.

This is not a raw JSON parser. Foundation can already coalesce canonically
equivalent duplicate keys before exposing `allKeys`; enumeration is not proof of
every serialized spelling. The regression also constructs BOTH ASCII and alias
spellings as raw JSON, with a backend digest covering both, and asserts refusal
without claiming that enumeration necessarily detects both. No parser redesign,
normalization of aliases, or blanket duplicate-key coverage is implied.
